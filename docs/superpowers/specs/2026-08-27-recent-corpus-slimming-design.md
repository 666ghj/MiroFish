# 最近3年派生语料瘦身设计

## 目标

在不修改原始上传文件和 `extracted_text.txt` 的前提下，为项目生成只包含最近3年高价值资料的派生语料，降低Graphiti建图规模、重复信息和LLM调用数量。

时间窗口按运行日期向前滚动3年。当前基准日期为2026-08-27，截止线为2023-08-27。

## 当前数据

- 原始文档段：105
- 原始提取文本：5,689,683字符
- 仅按日期过滤后：63段，约3,646,409字符
- 完整年度/中期报告约占2,670,649字符，与业绩公告存在大量重复
- 应用于建图的目标语料：约57段、975,760字符、约126个8000字符块

## 非目标

- 不删除或重命名上传文件。
- 不覆盖原始 `extracted_text.txt`。
- 不重新生成本体。
- 不使用LLM判断文档日期。
- 不自动删除历史失败图。

## 文档边界

沿用现有提取文本格式：

```text
=== 原始文件名 ===
文档正文
```

每个header到下一个header之间为一个独立文档段。解析结果必须保留原始顺序。

## 日期识别

识别优先级：

1. 文件名中的完整日期 `YYYY-MM-DD`、`YYYY/MM/DD` 或中文年月日。
2. 文件名中的年月 `YYYY-MM`，按该月最后一天判断。
3. 文件名中唯一明确年份；2024及以后纳入当前窗口，2022及以前排除。
4. 只有2023但无月日，标记为`ambiguous_date`，不自动纳入。
5. 完全无日期，标记为`undated`，不进入建图语料。

同一文件名出现多个日期时，以资料发布日期字段为先；无法区分时取最晚日期，并在审计清单记录`latest_date_fallback`。

## 内容选择规则

### 保留

- 截止线之后的业绩公告、业务更新、股东大会和业绩会记录。
- 截止线之后的券商研报、评级记录和目标价时间线。
- 截止线之后的创始团队演讲、采访、播客和公开发言。
- 截止线之后的媒体专题、行业数据和风险事件。

### 排除

- 截止线之前的资料。
- `00_索引`、覆盖矩阵、元数据库和研究总索引等二次导航文件。
- 完整年度报告和完整中期报告；保留同期间的业绩公告和业绩会纪要。
- `07_历史基线`资料。
- 无法可靠识别日期的资料。

排除完整报告只影响派生建图语料，原文件仍保留，可供人工阅读和报告引用。

## 输出

在项目目录生成：

- `extracted_text_recent_3y.txt`：派生语料，保持现有header格式。
- `corpus_recent_3y_manifest.json`：审计清单。

manifest结构：

```json
{
  "generated_at": "ISO-8601",
  "cutoff_date": "2023-08-27",
  "source_file": "extracted_text.txt",
  "output_file": "extracted_text_recent_3y.txt",
  "summary": {
    "total_sections": 105,
    "included_sections": 57,
    "excluded_sections": 48,
    "source_characters": 5689683,
    "output_characters": 975760
  },
  "documents": [
    {
      "name": "原始文件名",
      "detected_date": "2025-03-26",
      "date_source": "filename_full_date",
      "included": true,
      "reason": "within_window",
      "characters": 12345
    }
  ]
}
```

## API与项目模型

新增派生语料生成接口：

```text
POST /api/graph/project/<project_id>/corpus/recent
```

请求可选参数：

- `years`，固定支持正整数，默认3。
- `exclude_full_reports`，默认true。

响应返回manifest摘要和输出路径类型，不返回完整语料。

建图接口增加：

```json
{
  "project_id": "proj_xxx",
  "corpus": "recent_3y"
}
```

`corpus`允许：

- `full`：原始提取文本。
- `recent_3y`：派生语料；文件不存在时返回400，不隐式生成。

项目JSON增加可选字段：

- `active_corpus`
- `corpus_manifest`

默认仍为`full`，避免改变既有项目行为。

## 错误处理

- 原始提取文本不存在：404。
- 文档边界无法解析：400，不生成空文件。
- 输出写入失败：保留旧派生文件，使用临时文件原子替换。
- 派生结果为空：400并返回各排除原因计数。
- 日期解析异常：单文档标记`date_parse_error`并排除，不中断其他文档。

## 测试

- 多文档边界与顺序保持。
- 完整日期、年月、单年份和多日期解析。
- 截止日当天纳入。

- 完整报告排除、业绩公告保留。
- 索引/矩阵/历史基线排除。
- 原始文本不变化。
- manifest计数和字符数与派生文件一致。
- 临时文件原子替换。
- API生成、重复生成、缺失派生语料建图错误。

## 验收标准

- 原始105段及原文本哈希保持不变。
- 当前项目生成约57段、约97.6万字符派生语料；允许因精确日期解析产生小幅差异，差异必须体现在manifest。
